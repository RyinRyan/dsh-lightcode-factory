# 独立发布改造

## 目标与边界

DSH 是未修改的宿主，LightCode Factory 是独立安装包。平台、后端、Demo 三个业务插件保留原职责，安装入口只提供组合配置。原型目录不删除、不覆盖，用户模型配置和历史文件不迁移。

## 接口与装配

后端继续拥有任务状态、调度、持久化和评审。工作流通过 registerWorkflow 注册完整实现，按顺序等待 context.node；节点通过 report/log 上报有界观测并响应 AbortSignal。

后端浏览器插件通过原生 Remote $mount 注册自己的命名空间，不修改 DSH 的 remotes 包。页面通过原生 Slots 注册面板和侧栏，不修改宿主页面。

构建使用公开 npm 依赖、TypeScript 及 esbuild。通信 schema 与 Typert 注册描述由插件自身统一声明，避免公开生成器只能识别源码工作区依赖的问题。浏览器产物遵守 DSH ModuleLoader factory 格式，共享 React 和 Cordis，不私自携带第二份框架实例。包中不引用相邻 DSH 源码。

## 发布与安全

安装入口携带三个业务插件的构建产物；本地 tarball 验证完成后才能作为发布候选。此阶段不发布 npm，不触碰用户默认 DSH home，不把演示测试模型注入用户配置。原生工具与生成脚本仍使用 DSH 的权限策略。

安装包依赖进程内可信插件机制，不承诺隔离恶意第三方插件。当前仅支持顺序节点；无断点续跑和自动重试。卸载插件不应自动删除持久化历史。
